# JobMap product roadmap and progress

**Last updated:** 25 August 2026  
**Product direction:** Cameroon-first job discovery expanding to worldwide remote applications.

## Product thesis

JobMap will serve two connected use cases. **Cameroon Local** helps people find credible onsite and hybrid opportunities using cities, regions, radius search, and source provenance. **Global Remote** helps Cameroon-based applicants discover remote roles available internationally and move from job discovery to a prepared, user-reviewed application.

The product should compete with swipe-based autoapply tools through a stronger combination of **eligibility clarity, source trust, bilingual application preparation, and mobile convenience**. JobMap should not silently submit inaccurate or unwanted applications. Its default experience will be a hybrid: official APIs and explicitly approved integrations where available, plus guided browser-based applications with final user confirmation elsewhere.

## Confirmed decisions

| Decision | Product choice | Implication |
|---|---|---|
| Application method | **Hybrid** | Use official APIs or supported integrations where permitted; use guided browser-assisted flows for other employers. |
| Accounts | **Optional for discovery; required for persistence** | Anonymous users can browse. Email and Google sign-in unlock saved preferences, CVs, application history, alerts, and cross-device sync. |
| Audience | **Cameroon to the world** | The initial remote eligibility model is optimized for applicants located in Cameroon seeking worldwide remote work. The data model remains extensible to other applicant countries. |
| Device strategy | **Mobile-first PWA** | The mobile feed and swipe queue are primary; the Cameroon map is a powerful secondary view rather than the only home screen. |
| Simplify support | **Import, do not impersonate or scrape** | Support user-provided Simplify exports and resume/profile files. Do not request Simplify passwords or silently access private extension storage. |

## Core product modes

| Mode | Job types | Primary controls | Primary interface |
|---|---|---|---|
| Cameroon Local | Onsite and hybrid roles in Cameroon | Region, city, radius, sector, employment type, freshness, source trust | Feed plus map |
| Global Remote | Remote roles available to applicants in Cameroon or globally | Country eligibility, contractor/employee status, timezone overlap, language, salary, sponsorship, work mode | Feed plus swipe queue |

Every job should clearly state whether it is **Cameroon eligible**, **Africa eligible**, **worldwide remote**, **location unclear**, or **not eligible**. A remote label alone is not sufficient.

## ApplyFlow

ApplyFlow is the main growth feature. A user maintains one profile with contact details, professional history, skills, education, languages, timezone, work authorization, target roles, salary expectations, preferred contract type, and approved CV versions. Each job receives an explainable fit summary and an eligibility summary before the user invests time in applying.

When the user selects **Apply**, JobMap prepares an Application Pack consisting of the selected CV, a tailored profile summary, a concise cover message, and suggested answers to standard screening questions. The user reviews the pack, edits it if necessary, and then either opens the official application page or confirms a supported submission. Every application receives an audit record with the source, timestamp, documents used, answers submitted, and current status.

The safety boundary is intentional. JobMap may automate repetitive preparation and approved form filling, but it must not invent qualifications, answer sensitive questions without explicit user input, submit duplicate applications, or make employment decisions on the user’s behalf.

## Simplify import

Simplify’s official help documentation currently describes CSV import/export for its **Job Tracker**, with required fields including Company name and Position Title and optional Location. It also documents that Simplify Copilot stores profile, resume, and application information for its own autofill and tracking features, but the reviewed public documentation does not provide a documented public profile API or one-click profile export. [1] [2]

JobMap should therefore support the following import experience:

| Import lane | User input | JobMap result | Priority |
|---|---|---|---:|
| Simplify tracker import | Simplify-exported CSV | Import saved/applied jobs, map company, title, location, status, dates, links, and notes into JobMap Tracker | P0 |
| Resume/profile import | PDF or DOCX resume, or pasted profile text | Extract a draft profile for user review; preserve the original file as an approved CV version | P0 |
| Structured profile import | User-provided JSON/CSV generated by a future Simplify export or partner integration | Map skills, experience, education, languages, preferences, and screening answers | P1 |
| Browser handoff | Explicit user action from a future JobMap companion extension | Transfer selected fields into a JobMap import screen; never read Simplify private storage without an approved integration | P2 |

The import flow must show a field-mapping preview, identify conflicts, deduplicate jobs, and require confirmation before saving. It should never ask the user for Simplify credentials. Tracker import and profile import are separate because a tracker CSV is not the same thing as a reusable job profile.

## Mobile-first PWA experience

The primary mobile navigation should be **Discover, Swipe, Saved, Tracker, and Profile**. Job cards should support thumb actions, clear source and eligibility badges, readable typography, one-handed filters, accessible focus states, and fast loading on a constrained connection.

The PWA scope includes an installable manifest, icons, an offline application shell, cached saved jobs and tracker state, resilient loading states, shareable job URLs, mobile document upload, and opt-in notifications. Offline mode should never imply that a job is still open; freshness and last-verification timestamps must remain visible.

## Authentication and persistence

Discovery remains public. A user who wants to save preferences, upload documents, use ApplyFlow, track applications, or receive alerts signs in with **email or Google**. The account model should support verified email, provider identity, consent records, document metadata, profile versions, saved searches, applications, application events, and notification preferences.

The current static React application does not yet provide the required backend account and document infrastructure. The target implementation should migrate persistence to a hosted backend with a relational database and secure object storage. CV bytes belong in private file storage; the database should store only metadata and controlled references.

## Source strategy

Cameroon Local should prioritize FNE, ReliefWeb Cameroon, official institutions, verified employer career boards, universities, NGOs, and authorized local feeds. Global Remote should prioritize public feeds and official employer ATS endpoints that explicitly expose remote roles and eligibility information. Each source must preserve provenance, canonical application URL, freshness, expiry, and a source-health report.

Aggregators without a documented feed or permission should remain discovery candidates rather than being scraped. This applies to sources whose crawler policy limits use to search or reference. The feed should favor credible, current, attributable jobs over raw listing volume.

## Open risks and safeguards

Simplify import must remain user-initiated and should rely on documented exports or files the user provides. Employer application pages can change, restrict automation, or contain sensitive questions, so the product needs an allowlist, graceful fallback to guided handoff, and explicit final confirmation. Remote work eligibility is often ambiguous; JobMap should display uncertainty rather than overpromise. Personal documents and application answers require encryption, access controls, retention settings, and deletion support before public launch. User deletion requests should remove user-visible records immediately while retaining an access-restricted deletion tombstone and eligible backups for 90 days before purge.

## Database lifecycle milestone — 25 August 2026

The Supabase database now includes a Prisma-compatible application model and executable migration for profiles, profile versions, private CV metadata, shared sources and jobs, saved jobs, saved searches, applications, controlled application-answer memory, application events, consent records, notification preferences, and 90-day deletion requests. RLS is enabled for all thirteen public tables. User-owned policies are scoped to `auth.uid()`, shared catalog tables are read-only to clients, and CV Storage objects are path-scoped to the authenticated user. See [`zDocs/Database schema and RLS.md`](./Database%20schema%20and%20RLS.md).
